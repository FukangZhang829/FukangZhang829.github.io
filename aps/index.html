The Problem · 三个结构性痛点

航空制造一线调度员的真实困境，层层递进

基于多家航空主机厂与机载厂加工装配车间的实地调研，本课题识别出三个逐层递进的结构性痛点 —— 它们共同指向一个根因：排产领域缺少一套统一、可分析、可积累的语义基础设施。

01

🚨动态响应滞后 → 救火式调度

设备故障、物料延迟、任务插入等扰动发生时，现有 APS 需人工调整参数后触发全局重调度，计算耗时长。一线调度员被迫依赖个人经验即时判断，缺乏系统性的分析与推演支撑。

动态扰动 · 人工介入 · 全局重排
02

🔧局部微调没有工具支撑

真实生产中最高频的需求不是全局重排，而是局部微调——「某订单拖期，设备加班 2 小时能否解决？」。但不同工厂 APS 数据结构不同、约束建模不同、求解器格式不同，分析工作无法标准化，每次都需重写代码。

缺少统一排产表达语言
03

🧠排产经验无法结构化积累

老计划员的经验本质是一系列条件判断——「该机型此工位不宜排太紧」「A 类订单保交付、B 类可放宽换型」。缺少结构化表达与记录机制，经验随人员流动流失，新人只能从头积累。

The Solution · 两条主线

同一逻辑链的上下半场：语义表征 → 归因决策

本课题的核心命题不是「做一个更好的求解器」或「做一个对话排产助手」，而是：先建立统一排产语义表征层，使「分析约束的影响」成为可能；再在其上构建基于归因链推理的智能体，使「基于分析的优化决策」从经验驱动变为归因驱动。

主线一 · 语义基础

HiDAPS — 统一语义表征与标准化分析框架

排产领域长期缺少独立于数据源、独立于求解算法的统一表达语言。HiDAPS 建立以「约束语义化」本体层为底座的语义中间层：向下适配异构 APS 数据，向上提供标准化约束分析工具，横向使不同求解器的结果在同一坐标系下可比较。

约束语义化：35+ 约束类型、6 大类，带类型/严重度/可松弛性声明的一等公民
归因诊断器：输出结构化归因链——阻塞约束、贡献比例、松弛建议
统一实体映射：异构数据 → 统一概念表达，换工厂只改 YAML 配置
可插拔求解层：启发式 / 遗传 / DRL 接口统一注册，公平对比
主线二 · 决策延伸

APS Agent — 基于归因分析的自主优化闭环

在统一语义表征之上构建排产专用 Agent。Agent 不再机械地调用工具执行指令，而是基于 HiDAPS 暴露的约束归因关系进行推理：拿到归因链后判断主要矛盾、匹配松弛策略、在假设推演中安全验证、输出带证据链的推荐。

7 节点 LangGraph 状态图：上下文 → 意图 → 计划 → 决策 → 执行 → 确认 → 综合
L0–L3 分级智能：按任务复杂度分配推理资源

HiDAPS Engine · 语义中间层

约束携带语义、可自我松弛、可因果追溯

传统求解器将约束编译为数学不等式后丢失全部业务语义。HiDAPS 反过来——每条约束独立声明「约束谁、限制什么、严重程度、是否可放松、放松代价多大」，使 「分析 → 松弛 → 验证」成为可标准化的分析管道。

约束松弛引擎：冲突时的结构化缓冲

工业排产的约束必然互相矛盾。HiDAPS 的松弛引擎按代价排序试探——约束自己声明「可被放松到什么程度、代价多大」，引擎修改检查上下文而非约束本身，全程可审计。

松弛方法代价效果适用场景

Agent System · 决策编排

七节点状态图：控制流确定，推理流自由

执行流程是确定的有向图，节点流转由显式路由规则决定，而非由 LLM 自行判断「下一步去向」——大模型仅在推理决策节点内负责「选择哪个工具」。排产流程的走向必须可预期、可审计。Agent ⇄ Executor 构成「推理—执行—再推理」迭代循环。

Causal Decision Loop · 认知架构

四段式闭环：感知 → 归因 → 决策 → 验证

排产智能体的认知架构将「推理」与「验证」相分离——策略选择是推理的结果，其正确性无法仅凭推理保证；验证段以假设推演提供事实验证，使决策在「大胆假设、小心求证」的框架下进行。

Differentiation

不是又一个 LLM-Agent 项目

与通用 Agent 框架的本质区别：HiDAPS 提供了因果信息基础设施，Agent 基于归因链推理而非 prompt 猜测。
